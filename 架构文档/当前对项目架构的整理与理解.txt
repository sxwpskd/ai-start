# 一、项目架构理解（AI 助手整理于 2026-09-17，2026-09-18 补录 model 双体系等事实，2026-09-19 补录 B6 构思工作流通道与 B7 生成工作流通道，2026-09-20 补录 RAG 接入主流程、限流调整与仓库结构；本人对该项目的长期理解基准）

## 1. 项目定位
AI 零代码应用生成平台（ai-start）：用户输入自然语言描述，由 AI Agent 自动完成素材搜集、代码生成、质量检查、项目构建，最终一键部署为可访问的 Web 应用。本仓库为前后端单仓：后端 Spring Boot（端口 8100，context-path=/ai），前端为根目录 ai-start-frontend/（Vue 3 + Vite 独立构建），根目录含 README.md（开源说明）。

## 2. 技术栈
- 基础框架：Spring Boot 3.5.7 + Java 21（虚拟线程）
- AI 框架：LangChain4j 1.1.0（AiServices / 结构化输出 / 护轨 / 工具调用 / Redis 对话记忆）+ LangGraph4j 1.6.0-rc2（StateGraph / 条件边 / 并发分支 / 子图）
- ORM：MyBatis Flex 1.11.1（自定义代码生成器 MyBatisCodeGenerator）
- 缓存/会话：Redis（spring-session-data-redis 登录态、RedisChatMemoryStore 对话记忆、RedisCacheManager 业务缓存）+ Caffeine（AI Service 实例缓存）
- 限流：Redisson RRateLimiter + @RateLimit 注解 + AOP 切面
- 周边：Selenium + WebDriverManager（无头截图）、腾讯云 COS（封面存储）、Pexels API（图片搜索）、阿里云 DashScope wan2.2-t2i-flash（文生图）、Hutool、Knife4j、Lombok
- 大模型（application-local.yml）：DeepSeek —— deepseek-chat（通用/路由/流式）、deepseek-reasoner（推理，专用于 VUE_PROJECT 复杂代码生成）

  - UserController / ChatHistoryController（时间游标分页查历史）/ StaticResourceController（生成站点预览）/ WorkflowSseController（LangGraph 工作流演示：同步 / Flux / SseEmitter 三种方式）

## 4. 核心业务流程
1. 创建应用（POST /app/add）：codeGenType 空值默认 BASE（构思期）、首页显式选型直接落库（决策记录第 17 条）→ 入库（appName 取前 12 字符；旧 AI 路由调用注释保留备查）
2. 对话生成代码（GET /app/chat/gen/code，SSE）：登录校验 + 限流 → 存用户消息 → Facade → 工厂取（或建）AiCodeGeneratorService（Caffeine 缓存 + Redis 记忆 + DB 历史回灌）→ 流式输出给前端；流结束由 StreamHandlerExecutor 落库 AI 响应
3. 部署（POST /app/deploy）：校验权限 → 生成 6 位 deployKey → Vue 项目构建 dist → 复制到 {CODE_DEPLOY_ROOT_DIR}/{deployKey} → 更新 deployKey/deployedTime → 返回 URL → 虚拟线程异步截图 + COS 上传 + 更新封面
4. LangGraph 工作流（/workflow/*）：独立演示链路（CodeGenWorkflow 三版本 + SSE 演示），未接主业务；业务工作流走 AppController 的两个通道端点（见 5/6）
5. 构思工作流（POST /app/chat/think/workflow，B6 2026-09-19）：开关=开且 BASE 期 → thinkWorkflow 校验落库 → BaseWorkflowExecutor（虚拟线程+10min 超时）→ BaseWorkflow（rag 真检索 → ThinkNode：readThink 注入 → 无工具 AI → THINK_START/END 标记截取 → saveThink 成对重渲染）→ 同步返回 thinkReply 并落库（编码完成，联调验收待做）
6. 生成工作流（GET /app/gen/workflow，B7 2026-09-19）：开关=开触发生成 → genWorkflow 同步段校验鉴权 → GenWorkflowExecutor 虚拟线程内（RLock 按应用防重 → 先落用户消息 → 读 think 入 context.thinkContext → 生成图全流程 → 成功后统一落 codeGenType + genReply → finally 解锁）→ SSE 推送 progress（节点级 + 10s 心跳）→ done/business-error；超时 10min 定时守门中断；配套 GET /app/think/exists 预检端点（编码完成，前端接线与联调验收待做）
